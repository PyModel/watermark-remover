# v0.4.0 — PyPI distribution, service mode, and audit suite

Distribution release. v0.3.0 built the removal layers; v0.4.0 makes them reachable — the package is on PyPI, four console entry points replace `python path/to/script.py`, and a service mode, an audit suite, and container images wrap the same core. 29 commits, 144 files changed, 14 new modules, 33 new test files, 982 tests passing.

## Install

`watermark-remover` is now on PyPI. This is the first release you can `pip install`.

```bash
pip install watermark-remover
wm --help
```

The core still runs on Python 3.10+ using the standard library only. Networks, models, GPUs, and system binaries stay behind opt-in extras — `visible`, `quality`, `ai`, `provenance`, or `all`.

## Added

- **Packaging and console entry points.** `wm` (clean), `wm-serve` (HTTP service), `wm-audit-dir`, and `wm-audit-site`. The on-disk Claude-skill layout is preserved; the installed package is a single `watermark_remover` root.
- **HTTP service mode** (`wm-serve`) exposing clean, inspect, and detect over an API, so the same core can run behind a process boundary instead of a CLI invocation.
- **Audit suite** for directories, libraries, and websites — sweep a tree or a site for provenance signals rather than one file at a time.
- **Text-watermark detection**: detector adapters, a zero-LLM stylometry scorer, and a detection CLI wired to both.
- **Model-based rewrite pipeline** for Layer B, alongside the existing deterministic paths.
- **Pixel-level cleaning backends** and JPEG input accepted through a canonical raster boundary.
- **Broader metadata coverage** across container formats and image metadata, including detection as well as rewrite.
- **Container images and a compose stack**: a core service image plus opt-in heavy-backend harness images (`markllm`, `markdiffusion`), published to GHCR with SBOM and build provenance.
- **A lightweight `clean-user-facing-text` skill** for the common text-only case, with its own test suite.

## Changed

- **Breaking — `--api-key` is removed from `rewrite_text`.** Credentials are read exclusively from `WATERMARKS_REWRITE_API_KEY`, so keys are never passed on the command line where they land in shell history and process listings. Export the variable instead.
- **Unicode-hygiene engine rebuilt around protected spans**, so cleaning no longer touches regions that legitimately require the characters it strips.
- Embedded HEIF media now routes to the image pipeline rather than being treated as an opaque container.

## Fixed

- Embedded HEIF handling, PDF fallback to `pypdf` when `exiftool` runs but fails, and a set of detector review findings in the text-watermark path.

**Honesty contract:** deterministic cleaners report exactly what they removed. Rewrite, inpainting, spectral removal, and detector-evasion methods are labeled best-effort. Nothing here certifies that a vendor detector will fail.
